# 后端接入指南

> 给后端开发同学的一份说明：怎么拿到最新前端代码、怎么跑起来、接口契约在哪。
> 有问题随时在仓库提 issue 或直接联系前端。

## 1. 拿代码（GitHub）

前端会把仓库邀请你为协作者（ Collaborator ），接受邮件邀请后：

```bash
git clone https://github.com/shiziheng/sukaiui.git
cd sukaiui
```

- 仓库是私有仓库，需要 GitHub 账号被邀请。没收到邀请先找前端。
- **以后每次前端发新版本，直接 `git pull` 就是最新的**，不需要再要 zip 包。
- 想知道某次更新改了什么，看仓库根目录的 `CHANGELOG.md`，每个版本一节。
- 想锁定某个版本看代码，`git checkout v0.9.0`（tag 名与 CHANGELOG 对应）。

## 2. 跑起来

环境要求：Node >= 22.13.0

```bash
npm install                # 装依赖（package-lock.json 锁了版本）
npm run dev                # 起开发服务器，访问 http://localhost:5173
```

类型检查（改完代码建议跑）：

```bash
node node_modules/typescript/bin/tsc --noEmit -p tsconfig.json
```

注意：`npm run build` **不查类型**，类型问题要用上面这条命令查。

## 3. 先看这两份文档

| 文档 | 内容 |
|---|---|
| `docs/接口契约梳理.md` | **唯一对接文档**：建议的接口分组（A 交易支付 / B 代充批量 / C 账号凭据…）、前端当前的 Mock 实现位置、需要后端拍板的 8 个问题。以此为准设计接口 |
| `docs/产品说明书.md` + `docs/核心业务流程.md` | 网站有什么功能、每条业务流程的状态机长什么样。看完就知道前端演示了哪些场景 |

## 4. 代码结构速览

```
app/            页面入口（注意：路由只有 /，业务"页面"是组件状态切换，见下）
components/     全部 UI 组件（81 个文件，按业务命名：account-*、recharge-*、wallet-*…）
data/           所有 Mock 数据和假逻辑（对接时逐个替换成真接口调用的地方）
db/ drizzle/    脚手架自带的 ORM 配置，前端没实际使用，可忽略
```

**关键提醒**：本项目"页面"不是 URL 路由，是 `app/page.tsx` 里的 `selectedMenu` 状态切出来的。后端做「充值完成后跳回指定订单」这类深链跳转前，先看契约文档 §5 第 8 条，前端需要先改造成真实路由。

## 5. 后续协作方式

1. 前端每次发版本：push 到 `main` + 打 tag + 更新 `CHANGELOG.md`。
2. 后端拿代码：`git pull`，对照 CHANGELOG 看增量。
3. 契约有变化（接口增删、流程调整）：前端会同步更新 `docs/接口契约梳理.md` 并在 CHANGELOG 里注明。
