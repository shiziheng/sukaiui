# 虚拟卡与账单 · 后台接口需求清单

> 给后端同学的对接需求。前端（SUKAI UI Demo）目前全部用 Mock 演示，本文按**前台页面上的每个动作**列出需要后台提供的接口；同时附上运营后台（参考脑图）对应的接口，供统一设计数据模型。
>
> 金额单位统一为美元（USD，两位小数）；所有接口需要登录态；流水类接口统一支持分页 + 时间范围筛选。

---

## 一、虚拟卡（用户侧）

### 1. 开卡中心（开卡）

| # | 接口 | 说明 |
|---|---|---|
| 1 | `GET /cards/bins` | 卡段（BIN）列表。返回：bin、卡组织（Visa/MasterCard/Discover）、发行地、卡类型、支持场景文案、限制说明、开卡费、充值费率、消费费率、**剩余可开张数**。 |
| 2 | `GET /cards/bins/stock-summary` | 整体剩余开卡数（全部卡段加总），开卡中心顶部展示。 |
| 3 | `POST /cards/open` | 开卡。参数：binId、数量（1–10）。后台扣平台余额（开卡费 × 数量，**费用外扣**），返回新卡列表（卡号、有效期、持卡人、账单地址）。失败要返回明确错误（余额不足 / 库存不足 / 上游失败）。 |
| 4 | `GET /cards/scenes` | 卡支持场景文案。要求**后台可配置**（按卡段维护，前台只读展示）。 |

### 2. 卡列表 / 卡详情

| # | 接口 | 说明 |
|---|---|---|
| 5 | `GET /cards` | 我的卡片列表。参数：状态、关键词、卡组织、发行地、排序、分页。状态枚举：**已激活 active / 已冻结 frozen（用户冻结）/ 系统冻结 system_frozen（平台或上游冻结）**。返回含脱敏卡号（前4后4明文，中间密文由前端拼或后台直接给）。 |
| 6 | `GET /cards/{id}` | 卡详情：卡号、有效期、持卡人信息、账单地址、开卡时间、卡内余额、状态、备注。 |
| 7 | `GET /cards/{id}/cvv` | **CVV 实时查询**：前端点击「查询 CVV」时调用，由后台向上游实时查询后返回。**系统不存储 CVV**，不要落库；建议加频控（如 60 秒内限次）与审计日志。 |
| 8 | `POST /cards/{id}/freeze`、`POST /cards/{id}/unfreeze` | 冻结 / 解冻（用户自己操作）。系统冻结的卡不允许用户解冻，接口要校验并返回错误。 |
| 9 | `POST /cards/{id}/refund` | **卡退款**：卡内全部余额退回平台余额，卡余额清零。注意：部分卡段退款会触发上游封卡，接口应返回该卡段是否允许退款。 |
| 10 | `DELETE /cards/{id}` | 删卡（销卡）：余额退回平台余额；**该卡的历史流水必须保留**（前台交易记录显示「已销卡」）。 |
| 11 | `GET /cards/export` | 卡列表导出 CSV（前台导出按钮；也可前端用列表数据本地生成，二选一，后台定）。 |

### 3. 卡片充值

| # | 接口 | 说明 |
|---|---|---|
| 12 | `POST /cards/{id}/recharge` | 卡充值：平台余额 → 卡内余额。参数：金额。后台按卡段充值费率计费（**费用外扣**），返回划转结果与变动后余额。 |
| 13 | `GET /cards/transactions` | 卡消费流水（全部卡）。参数：卡号、类型（充值/消费/退款/手续费）、关键词（商户/交易号）、时间范围、分页。销卡的卡流水也要能查到。 |
| 14 | `GET /cards/{id}/transactions` | 单卡流水（卡详情页「本卡流水」）。 |

## 二、钱包/充值 · 余额流水

平台余额的所有变动集中在一个流水表里，前台「钱包/充值」页展示：

| # | 接口 | 说明 |
|---|---|---|
| 15 | `GET /wallet/flows` | 平台余额流水。类型枚举：**平台充值 topup / 开卡扣费 card_open / 卡充值 card_recharge / 卡退款 card_refund / 销卡退款 card_close**（预留：消费扣款、代充扣款）。返回：时间、类型、金额（正入负出）、变动后余额、说明、流水号、状态。 |
| 16 | `GET /wallet/balance` | 当前平台余额（前台顶部余额条与开卡/充值校验用）。 |

## 三、我的账单 · 平台流水

| # | 接口 | 说明 |
|---|---|---|
| 17 | `GET /bills/flows` | 平台其他流水，按类型筛选：**代充流水 / 成品号流水 / 退单·返佣**（卡流水走接口 13/14，前台会把两边合在一个筛选器里）。返回：时间、类型、标题、金额、变动后余额、关联单号、状态。 |
| 18 | `GET /orders` | 我的订单（保留现有订单列表）：成品号订单 + 代充订单，支持状态/时间/关键词筛选与分页。 |

## 四、运营后台（参考脑图，统一数据模型用）

以下为运营侧功能，前台不开发界面，但**数据模型和配置项会被前台读到**，请一并设计：

### 卡段管理（对应前台「卡段/BIN」）
- 卡段 CRUD：选择上游、同步卡段（从上游拉取 BIN）、编辑、停用/启用、手动刷新、分配卡段。
- 前台读到的字段：BIN、卡组织、发行地、卡类型、**支持场景文案（后台定义）**、限制说明、费率、剩余库存。

### 费率配置
- 费率管理：**开卡费、验证费、杂值费、小额管理费**（前台当前只展示开卡费 + 充值费率，字段请预留）。
- 卡段定价：按卡段单独定价。
- 用户独立费率：支持按用户覆盖默认费率（双入口：费率配置页 / 用户列表页）。

### 虚拟卡商品管理（开卡中心的商品化）
- 商品 CRUD：商品名称、关联卡商、关联卡段、资费（默认从资费包获取 / 未设资费包用默认资费）、抵押金额、批量开卡金额、持卡人、卡片信息、**前台展示费用信息**、启用/停用。
- 前台开卡中心建议逐步迁移为「商品」维度（当前是卡段维度），接口设计请预留 `productId`。

### 订单管理
- 虚拟卡订单：开卡订单（张数、卡段、金额、状态：已出卡/开卡中/失败出数）。
- 账户流水类型扩展：在现有类型上**增加：开卡、销卡、卡冻结、卡退款**（与接口 15 的类型枚举保持一致）。

### 上游管理
- 上游渠道 CRUD：上游名称、接入配置、状态。卡段同步与 CVV 实时查询都依赖上游通道。

## 五、需要后台确认的问题

1. **CVV 查询的频控与审计**：前端点击即查，建议限次 + 日志，超限返回明确错误码。
2. **退款的封卡风险**：卡段维度是否允许退款，需要接口返回（前台弹窗提示用）。
3. **销卡流水的归属**：销卡后流水保留在原卡号下，卡列表不可见、交易记录可见——请确认流水查询接口对已销卡的处理。
4. **开卡数量上限**：前台限制单笔 1–10 张，整体剩余开卡数是否需要按用户维度再加限制。
5. **余额流水与账单流水的拆分**：目前前台口径 = 余额相关变动进「钱包/充值」，业务流水（代充/成品号/返佣）进「我的账单」，请确认后台是否同一张表不同类型。
