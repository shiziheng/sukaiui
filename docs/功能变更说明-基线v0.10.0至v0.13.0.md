## 四、新增功能详解

每个功能按固定模板写：**是什么 → 用户动作 → 后台要做什么 → 业务规则 → 验收标准**。接口编号对应《接口需求》。

### F1 开卡中心（新页面，虚拟卡页第一个子页签）

- **是什么**：用户按卡段（BIN）挑选并开通虚拟卡的入口。
- **用户动作**：① 查看卡段列表（卡组织 Visa/MasterCard/Discover、发行地、场景、费用）；② 看整体剩余开卡数（所有卡段加总，页面顶部展示）；③ 选卡段 + 数量（1–10 张）→ 确认开卡 → 余额直付成功出新卡。
- **后台要做什么**：
  - 接口 #1 卡段列表、#2 整体剩余库存、#3 开卡、#4 场景文案（后台可配置）。
  - 开卡时扣费 = 开卡费 × 数量，从平台余额扣，**费用外扣**（不进卡内余额）。
  - 开卡失败必须返回明确错误：余额不足 / 库存不足 / 上游失败（前端要分开提示）。
  - 生成**开卡订单**（张数、卡段、金额、状态：已出卡/开卡中/失败），供订单管理使用。
- **业务规则**：单笔上限 10 张；卡余额初始为 0；开卡成功写钱包流水 `card_open`。
- **验收**：余额不足时前端弹充值引导且不产生半成品卡；库存不足被拒绝；重复提交不重复扣费。

### F2 我的卡片（卡列表）

- **是什么**：用户持卡列表，支持卡片/表格两种视图。
- **用户动作**：搜索（卡号/备注）+ 四个下拉筛选（状态、卡组织、发行地、排序）→ 查看卡面 → 操作：充值 / 卡详情 / 冻结 / 注销 / **退款** / **导出 CSV**。顶部一条数据栏：平台余额、卡片总数、卡内总余额、冻结中、已注销。
- **后台要做什么**：接口 #5 卡列表（筛选/排序/分页）、#9 卡退款、#10 删卡、#11 导出。
- **业务规则**：
  - 状态枚举见第五节；**系统冻结的卡不允许用户解冻**（接口 #8 需校验）。
  - 注销 = 删卡：卡内余额退回平台余额，写 `card_close` 流水，卡进入「已注销」筛选视图（灰显 + 注销时间），**历史流水必须保留**。
  - 卡号脱敏统一口径：**前 4 后 4 明文，中间密文**（由后台返回或前端拼接，二选一）。
- **验收**：切「已注销」能查到删卡记录；筛选组合正确；卡内总余额 = 所有未注销卡余额之和。

### F3 卡详情

- **是什么**：单卡全量信息 + 本卡统计 + 本卡流水。
- **用户动作**：查看卡号/有效期/CVV/持卡人/账单地址/状态/累计充值·消费·退款；点「查询 CVV」实时取值；导出本卡流水。
- **后台要做什么**：接口 #6 卡详情、**#7 CVV 实时查询（重点，见下）**、#14 单卡流水。
- **CVV 规则（安全红线）**：**系统不存储 CVV、不落库**。前端点击时后台实时向上游查询后返回（前端展示约 1 秒延迟）。需频控（建议 60 秒内限次）+ 审计日志，超限返回明确错误码。
- **验收**：数据库任何表查不到 CVV 明文；CVV 查询有审计记录；已冻结/已注销卡 CVV 查询被拒绝。

### F4 卡充值 / 卡退款 / 销卡（卡资金三件套）

- **是什么**：卡与平台余额之间的资金通道。**卡内余额不是独立充值渠道，全部来自平台余额划转**。
- **用户动作与资金方向**：
  - 卡充值：平台余额 → 卡内余额（接口 #12），按卡段充值费率计费，**费用外扣**（从平台余额另扣，不占划转金额）。
  - 卡退款：卡内全部余额 → 平台余额（接口 #9），卡余额清零。**部分卡段退款会触发上游封卡**，接口需返回该卡段是否允许退款，前端据此弹提示。
  - 销卡：余额退回 + 卡注销（接口 #10），同 F2 规则。
- **每笔操作都要**：① 变更双方余额；② 写对应类型流水（`card_recharge` / `card_refund` / `card_close`）；③ 失败可回滚，不留脏数据。
- **验收**：任意卡的生命周期「开卡 → 充值 → 消费 → 退款 → 销卡」走完，平台余额变动总额与流水记录能对平。

### F5 交易记录（卡流水，全局）

- **是什么**：虚拟卡页第三个子页签，全部卡的流水。
- **用户动作**：按卡号、类型（充值/消费/退款/手续费）、关键词（商户/交易号）筛选。
- **后台要做什么**：接口 #13 全局卡流水。**销卡的卡流水也要能查到**，前端在卡列和筛选下拉显示「已销卡」。
- **验收**：销一张卡后，其历史流水在交易记录仍可见且标注已销卡。

### F6 钱包/充值 · 余额流水（v0.13.0 新增区块）

- **是什么**：平台余额每一笔变动的统一流水表，嵌在充值页下方。
- **后台要做什么**：接口 #15 余额流水、#16 当前余额。
- **类型枚举（新增 4 类，扩展到既有流水表）**：
  | 类型 | 编码 | 方向 |
  |---|---|---|
  | 平台充值 | `topup` | 入 |
  | **开卡扣费** | `card_open` | 出 |
  | **卡充值** | `card_recharge` | 出 |
  | **卡退款** | `card_refund` | 入 |
  | **销卡退款** | `card_close` | 入 |
  | 消费扣款 / 代充扣款 | （预留） | 出 |
- **业务规则**：每条流水含时间、类型、金额（正入负出）、变动后余额、说明、流水号、状态。开卡/充值/退款/销卡操作**实时**写入（前台演示是即时出现的，不接受延迟对账）。
- **验收**：F1–F4 的每笔操作都能在余额流水里按时间倒序看到，金额与变动后余额连贯。

### F7 我的账单（基线「我的订单」升级）

- **是什么**：双视图页面。视图一「平台流水」：代充流水 / 成品号流水 / 退单·返佣 / 卡流水四类筛选；视图二「我的订单」：沿用基线订单列表。
- **后台要做什么**：接口 #17 平台业务流水（按类型筛选）、#18 订单列表（沿用现有）。
- **业务规则**：**口径拆分**——余额相关变动进「钱包/充值·余额流水」（F6），业务流水（代充/成品号/返佣）进「我的账单·平台流水」（F7），卡流水两边都可能出现（账单页的卡流水筛选项实际拉接口 #13）。待确认后台是否同一张表不同类型（见《接口需求》第五节问题 5）。
- **验收**：四类筛选各自返回正确数据；「我的订单」视图与基线行为一致。

## 五、数据模型与枚举汇总（AI 建表/建枚举直接参照）

### 新增实体

**CardBin（卡段）**：bin、卡组织 scheme、发行地 region、卡类型、支持场景文案（后台可配置）、限制说明、开卡费 openFee、充值费率 rechargeRate、消费费率 consumeRate、剩余库存 remainingStock、状态（启用/停用）、预留 `productId`（开卡中心未来迁移为「商品」维度）。

**VirtualCard（虚拟卡）**：id、卡号（脱敏前4后4）、有效期、持卡人、账单地址、卡内余额、状态 status、关联 binId、开卡时间、备注、注销时间 closedAt。**没有 CVV 字段——不许存储。**

**ClosedCardRecord（删卡记录）**：注销时点的卡片快照 + 注销时间。可不单独建表（用卡状态 + closedAt 实现），但列表接口要能按「已注销」筛出。

**CardFlow（卡流水）**：id、cardId、卡号、类型 type、金额、商户、交易号、状态、时间。**销卡后保留，不级联删除。**

**WalletFlow（平台余额流水）**：id、类型 type（F6 枚举）、金额（正入负出）、变动后余额 balanceAfter、说明、流水号、状态、时间。可与基线账户流水同表加类型，或独立表——二选一待确认。

**CardOpenOrder（开卡订单）**：张数、卡段、金额、状态（已出卡 / 开卡中 / 失败）。挂到现有订单体系下。

### 枚举

| 枚举 | 取值 |
|---|---|
| 卡状态 | `active` 已激活 / `frozen` 已冻结（用户）/ `system_frozen` 系统冻结（平台或上游）/ `processing` 开卡中 / `closed` 已注销 |
| 卡组织 | Visa / MasterCard / Discover |
| 余额流水类型 | `topup` / `card_open` / `card_recharge` / `card_refund` / `card_close`（预留：消费、代充扣款） |
| 卡流水类型 | 充值 / 消费 / 退款 / 手续费 |
| 账单流水类型 | 代充流水 / 成品号流水 / 退单·返佣 / 卡流水 |
| 开卡订单状态 | 已出卡 / 开卡中 / 失败 |

### 与既有系统的关系

- **平台余额**：卡业务的资金源头与终点。开卡费、卡充值从平台余额出；卡退款、销卡退款回平台余额。余额扣减必须与流水同事务。
- **订单体系**：新增开卡订单类型，复用现有订单查询（接口 #18）。
- **账户流水**：在基线类型上**扩展**开卡/销卡/卡冻结/卡退款，不是新表推翻重来。

## 六、验收清单（AI/后端自检用）

- [ ] 开卡：扣费 = 开卡费 × 数量（费用外扣），余额/库存校验，失败有明确错误码，生成开卡订单
- [ ] 卡列表：五状态筛选 + 卡组织/发行地/排序/分页；「已注销」可查删卡记录
- [ ] 卡号统一前 4 后 4 明文脱敏
- [ ] CVV：实时查上游、不落库、有频控、有审计日志
- [ ] 冻结/解冻：系统冻结卡拒绝用户解冻
- [ ] 卡充值/退款/销卡：双方余额同事务变更 + 写流水；退款返回是否触发上游封卡
- [ ] 销卡后历史流水保留且可查（全局 + 单卡）
- [ ] 余额流水：5 类卡相关变动实时写入，含变动后余额
- [ ] 账单流水：四类筛选正确，订单视图不回归
- [ ] 对平测试：任意卡全生命周期走完后，平台余额总额 = 充值入 − 各项出，与流水逐条可对

## 七、遗留待确认问题

沿用《接口需求》第五节的 5 个问题：CVV 频控口径、退款封卡风险返回方式、销卡流水归属、开卡数是否按用户限总量、余额流水与账单流水是否同表。这 5 项不阻塞开发，但排期前需要后台拍板。
