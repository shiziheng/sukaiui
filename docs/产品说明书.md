## 一句话定位

SUKAI 速开是一个 **GPT / Claude 账号与订阅服务平台**的纯前端 Demo：帮用户**买现成账号（成品号）**、**给自己的账号升级套餐（代充）**、**给钱包充值**，配套用户中心和站内信。当前阶段**只做前端页面展示**，全部数据为 Mock，无后端、无真实支付、无真实鉴权。

## 四大功能块

### 1. 成品号（买现成账号）

- **商品**：ChatGPT Plus / Pro、Claude Pro 等成品号，按地区（美区/东南亚等）与套餐区分；部分商品限购（`maxQuantity: 9`）。商品数据在 `data/products.ts`
- **购买方式**：点「立即购买」→ 居中弹窗 `AccountPurchaseDialog`（确认购买 → 支付成功两段）→ **100% 扣钱包余额直付**，无链上环节
- **余额不足**：自动挂起订单并跳钱包充值页；充值成功后可点「返回订单继续支付」续付
- **Mock 边界**：下单不创建真实订单、扣款只改前端余额 state

### 2. 套餐代充（升级自己的账号）

- **两种模式**：单账号办理 / 批量办理（可随时互相切换）
- **单账号**：选品牌（ChatGPT / Claude）→ 选套餐（Plus / Pro / Max）→ 填账号信息提交
- **批量**：粘贴多个 Session 批量解析（成功/失败/解析中三种状态），仅 Free 账号可办，逐条查看结果
- **Mock 边界**：Session 解析与套餐变更全是前端模拟，不触碰真实账号

### 3. 钱包充值（USDT 链上充值）

- **三步流程**：① 选充值金额 → ② 选支付网络（TRC20 / ERC20）→ ③ 扫码支付
- **扫码页要素**：支付状态 + 倒计时、应付金额、**充值单号**（PAY 开头）、**小数点尾数高亮提醒**、到账金额、收款地址（可复制）+ 二维码
- **「查询到账状态」**：演示两段式——第一次点击模拟"检测到转账（链上确认中）"，再次点击完成到账
- **到账后**：余额累加，生成充值记录（RCG 开头单号），页面下方充值记录可恢复待支付单
- **Mock 边界**：支付确认由「查询到账状态」按钮驱动，不发任何网络请求

### 4. 站内信（右上角铃铛，登录后可见）

- **消息类型**：全局消息 + 按邮箱匹配的个人消息（面板内输入邮箱查看专属消息，示例 `vip@example.com` / `test@sukai.com`）
- **消息属性**：标题、内容、是否强制弹出、上架/下架/过期状态
- **交互规则**：未读角标计数；面板默认展示最新 2 条，更多进「全部消息」；点标题看详情并自动已读；强制消息仅对未读用户弹一次，确认后不再弹；下架/过期消息不可见、不弹窗、不计未读
- **数据**：`data/messages.ts`；已读状态与邮箱存 localStorage
- **Mock 边界**：无后台发送入口，消息为预置数据；后端接入后按契约替换数据源

## 账号体系（演示级）

- **登录**：一键 Mock 登录（`handleDemoLogin`），点登录即进入登录态，无密码无鉴权
- **注册**：同样为演示入口
- **游客态**：只能看落地页；任何下单入口会先执行一键登录再继续

## 数据与文案在哪改

| 内容 | 位置 |
|------|------|
| 商品、订单、充值记录、钱包流水等 Mock | `data/` 各文件 |
| 全站可编辑文案（导航、按钮、标题……） | `data/content.ts`（登录后右上角「编辑文案」模式可实时改） |
| 站内信消息 | `data/messages.ts` |
| 支付网络与地址 | `data/payment-mocks.ts` |
| 页面级文案迁移（改默认值必读） | `app/page.tsx` 的 localStorage 迁移段——**改已有文案默认值必须补链式迁移**，否则老用户永远卡旧文案 |

## 与后端的分工

- 前端只做页面展示与交互，**不做后台接口**；所有"将来要真的"的数据点都已在 `docs/接口契约梳理.md` 里梳理了结构
- 后端从 GitHub 获取最新代码，按契约实现接口、替换 `data/` 中的 Mock，前端 UI 逻辑不变
