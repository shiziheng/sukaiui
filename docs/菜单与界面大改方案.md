# 菜单与界面大改方案（v1 提案）

> 2026-10-22 · 基于登录态实机走查（1440 / 1296 宽，886 高）
> 目标：**入口少、层级浅、动作明确、每屏只有一个主角。**
> 配套线框预览：`docs/nav-redesign-preview.html`

---

## 0. 一句话结论

现在不是“菜单样式不好看”，而是**导航在替产品做信息架构**：

- 15 个可见入口、2 级树、5 个二级项常驻展开；
- 同一个功能最多有 3～4 个入口（侧栏、头像菜单、顶栏、首页快捷入口）；
- “页面”和“动作”混在同一层（在线客服、站内信和账户安全并排）；
- 顶栏 6 组常驻操作，其中“编辑文案”“版式”属于演示工具，却一直占着客户视线。

**大改方向：侧栏只留 5 个一级入口，二级全部变成页内页签，演示工具退出主界面。**

---

## 1. 实机走查：6 个具体症状

### 1.1 入口太多，侧栏像一棵展开的树

当前侧栏（登录后）实际可见 **15 项**：

```
主菜单：首页 / 我的钱包 / 卡片 / 商城 / 账单 / 推广
        └ 卡片：我的卡片 / 开卡中心 / 卡流水
        └ 商城：套餐代充 / 成品号
更多：  在线客服 / 站内信 / 账户与安全 / 个人中心
```

在 886px 高的窗口里，5 个二级项全部展开，侧栏导航刚好铺满，再多一项就要滚动。用户第一眼看到的是“结构”，不是“我要办的事”。

### 1.2 同一功能有 2～4 个入口

| 功能 | 现在能在哪里进 | 次数 |
|---|---|---|
| 钱包 | 侧栏 / 头像菜单 / 首页快捷入口 / 顶栏“平台余额” | 4 |
| 推广 | 侧栏 / 头像菜单 / 首页快捷入口 | 3 |
| 在线客服 | 侧栏 / 顶栏 / 首页快捷入口 | 3 |
| 账户与安全 | 侧栏 / 头像菜单 | 2 |
| 站内信 | 侧栏 / 顶栏铃铛 | 2 |
| 个人中心 | 侧栏 / 头像菜单 | 2 |
| 卡片 | 侧栏 / 顶栏“卡内余额” | 2 |
| 订单 | 侧栏 / 首页快捷入口“交易记录” | 2 |

入口重复不会让用户觉得方便，只会让用户每次都要重新判断“刚才那个是不是同一个地方”。

### 1.3 命名是两套系统

- 菜单叫「我的钱包」，页面标题叫「钱包」；
- 菜单叫「账单」，页面标题叫「我的账单」；
- 菜单叫「推广」，页面标题叫「我的邀请」；
- 父项叫「卡片」，第一个子项也叫「我的卡片」；
- 顶栏写「平台 / 卡内」，钱包里叫「可用余额 / 冻结金额」。

用户需要做“翻译”，这是认知税。

### 1.4 顶栏常驻操作过多

1296px 宽下，顶栏右侧操作区实测 **657px**，包含：

`编辑文案(92) + 平台余额(124) + 卡内余额(124) + 铃铛(32) + 在线客服(103) + 用户菜单(153)`

顶栏是“告诉你在哪、有多少钱”的地方，现在变成了第二个功能入口区。尤其「编辑文案」——这是内部演示工具，不应该出现在客户默认视图里。

### 1.5 页面重心不在“下一步做什么”

| 页面 | 页面高度 | 相当于 886px 视口 |
|---|---:|---:|
| 首页（数据总览） | 1859px | 2.1 屏 |
| 账单 | 2214px | 2.5 屏 |
| 充值 | 2520px | 2.8 屏 |

充值页首屏同时出现：步骤条、金额输入、快捷档位、充值摘要、流程说明、最近充值记录、余额流水、FAQ。用户只想充 100 USDT，却要先穿过一个“说明书”。

### 1.6 首页是“经营看板”，不是“用户首页”

当前首页首屏是：本月消费金额、今日成功金额、今日失败金额、拒付率、消费趋势、运营指标、订单状态分布、实时交易动态。

这是**平台运营视角**，不是买家视角。普通用户看到“今日失败金额 / 拒付率”，第一反应是“我的账号是不是有问题？”。首页应该先回答三个问题：

1. 我还有多少钱？
2. 有没有正在处理的订单？
3. 我现在要办事，点哪里？

## 2. 诊断：乱的不是颜色，是层级

| 根因 | 表现 | 后果 |
|---|---|---|
| 容器和页面同级 | 「商城」既是页面又是父级；「卡片」既是页面又是父级 | 用户不知道点父项会发生什么 |
| 页面和动作同级 | 「在线客服 / 站内信」是浮层动作，却和「账户与安全」并排 | 导航不可预测 |
| 入口不唯一 | 钱包、推广、客服各有 2～4 个入口 | 用户记不住位置 |
| 常驻工具太多 | 版式、编辑文案、两个余额、客服、铃铛 | 顶栏拥挤，主次不分 |
| 页面不聚焦 | 充值页把流程、帮助、历史全铺开 | 完成任务的路径变长 |

所以本方案**不先改圆角、字号和颜色**，先做“减法”和“归位”。

## 3. 新信息架构：5 + 1

### 3.1 一级导航只留 5 个

| 新入口 | 里面有什么 | 默认落地 | 收编了谁 |
|---|---|---|---|
| **首页** | 余额、待办、进行中订单、最近订单、三个快捷动作 | 个人总览 | 现「首页」 |
| **商城** | 页内页签：套餐代充 / 成品号 | 套餐代充 | 现「商城」+ 2 个二级 |
| **卡片** | 页内页签：我的卡片 / 开卡中心 / 卡流水 | 我的卡片 | 现「卡片」+ 3 个二级 |
| **钱包** | 余额、充值入口、资金流水、充值记录 | 钱包总览 | 现「我的钱包」；充值不再单独占导航 |
| **订单** | 页内页签：订单 / 资金流水 | 订单 | 现「账单」 |

底部固定的 **「我的」**（桌面为侧栏底部用户卡，移动端为第 6 个底栏项）：

- 个人资料
- 账户设置（资料 + 安全合并，页内页签）
- 推广奖励
- 演示工具（编辑文案 / 导配置 / 恢复默认）
- 退出登录

### 3.2 页内页签替代侧栏二级

```
商城
  [套餐代充] [成品号]

卡片
  [我的卡片] [开卡中心] [卡流水]

订单
  [订单] [资金流水]

钱包
  [资金流水] [充值记录] [冻结明细]
```

侧栏不再展开任何二级项。用户在页面里切换，视线不离开内容区。

### 3.3 顶栏只保留 4 件事

```
[侧栏开关] 商城 · 成品号              [可用余额 $359.96  +]  [🔔]  [🎧]  [H]
```

- **一个余额**：默认显示平台可用余额，点击进钱包，`+` 直接进充值；卡内余额只在卡片页/钱包页出现。
- **站内信**：保留铃铛，这是高频通知，不需要进导航。
- **在线客服**：保留一个耳机图标，替代侧栏、首页、顶栏三处入口。
- **用户头像**：只保留「我的 / 退出」，不再重复放钱包、推广、安全。
- **编辑文案**：移入「我的 → 演示工具」，默认对客户不可见。
- **版式设置**：删除。侧栏只保留一个“收起/展开”按钮。

### 3.4 导航对照

| 现在 | 改后 |
|---|---|
| 侧栏 15 项，2 级 | 侧栏 5 项 + 底部「我的」，0 级 |
| 顶栏 6 组操作 | 顶栏 4 组 |
| 面包屑「工作台 / 卡片 / 我的卡片」 | 「卡片 · 我的卡片」两段，或只在折叠态显示 |
| 充值单独成页、从侧栏外进入 | 从余额、钱包、余额不足流程进入，页面保留深链 |
| 帮助中心藏在客服卡 | 保留，不占导航 |

## 4. 界面大改：每页只留一个主角

### 4.1 首页：从“经营看板”改成“我的总览”

**首屏只做 3 件事：**

```
晚上好，Heman123
[可用余额 $359.96]   [待处理订单 1]   [卡内余额 $414.98]

[去充值]  [买成品号]  [办代充]  [开卡]

进行中的订单
  订单号 / 商品 / 进度 / 继续支付

最近订单（3～5 条）                    查看全部 →
```

- 运营指标（消费趋势、拒付率、成功率）移到「经营视图」或独立报表页。
- 如果产品同时服务“普通买家”和“分销/运营”，在头像菜单提供「切换经营视图」，不要默认展示。
- 首页高度目标：**≤ 1100px（1.2 屏）**。

### 4.2 商城：一个页面，两个页签

- 顶部：`套餐代充 | 成品号` 分段控件，下面才是商品。
- 商品卡只保留 4 个判断点：**品牌 / 套餐 / 价格 / 库存**；卖点最多 3 条。
- 「立即办理 / 立即购买」是卡片唯一主按钮，其余说明收进详情。
- FAQ 放到页面底部默认折叠，不占首屏。
- 去掉页内重复的「ChatGPT / Claude」大标题和重复副标题。

### 4.3 卡片：页签进页面，筛选收成一行

- 页内页签：我的卡片 / 开卡中心 / 卡流水。
- 筛选条只留：`状态` `卡组织` `排序` `搜索尾号`；更多条件进「筛选」弹层。
- 卡片本身：余额最大，卡号尾号 + BIN 次之；`充值` 主按钮，`卡详情` 次按钮，冻结/备注/删卡进 `···`。
- 窄屏不再重复出现页签，改为顶部横向滚动页签。

### 4.4 钱包：余额是唯一主角

- 首屏：可用余额（大数字）+ 冻结金额 + 积分，右侧/下方一个 `充值` 主按钮。
- 快捷操作从 6 个减到 3 个：`充值` / `买成品号` / `办代充`；流水、充值记录、冻结明细改成页内页签。
- 充值页做“专注模式”：
  - 顶部：返回 + 步骤 1/3；
  - 步骤 1：金额 + 快捷档位 + 右侧粘性摘要；
  - 步骤 2：两张网络卡；
  - 步骤 3：二维码 + 状态 + 金额 + 地址，唯一主按钮「我已转账，查询到账」；
  - 流程说明、FAQ 收进 `?`，历史记录回钱包看。
- 充值页高度目标：**≤ 1400px（1.5 屏）**。

### 4.5 订单：默认落在“订单”，不是“流水”

- 页内页签：`订单 | 资金流水`，默认「订单」。
- 顶部状态卡保留 4 个，窄屏折叠成横向滚动。
- 筛选收成一行：搜索 / 时间 / 状态；类型用 chips。
- 订单详情继续用现有抽屉，不新开页面。

### 4.6 我的：把四个“更多”收进一个地方

原来「更多」里的 4 项 + 头像菜单 5 项，合并为：

```
我的
  Heman123
  shizheng134@gmail.com

  个人资料      →
  账户设置      →     （资料 / 安全 两个页签）
  推广奖励      →
  ─────────────
  演示工具      →     （编辑文案 / 导出配置 / 恢复默认）
  退出登录
```

- 在线客服和站内信在顶栏，不再进「我的」。
- 帮助中心从客服卡进入，保留 `#help` 深链。

## 5. 视觉与交互统一

### 5.1 去掉“每页一个风格”

当前页面里至少有 3 套页头：`uc-page-heading`、`commerce-page-heading`、`dash-hero`。统一成一套 `PageHeader`：

```
[图标] 页面标题                         [唯一主操作]
       一句话说明
       [页内页签]
```

- 标题 28px / 700；说明 14px / 常规；页签 14px。
- 页面左右留白统一 32px（移动端 16px）。
- 所有页面标题与左侧菜单文字**完全一致**。

### 5.2 颜色只做一件事

- 荧光绿只用于：**主按钮 + 当前导航指示 + 关键数字**。
- 不再用于：每个 KPI 的圆点、每个图标、每个标签、每个 hover。
- 其余用中性色：深色侧栏 `#111214`，页面底 `#F6F7F2`，卡片白 `#FFFFFF`，边框 `#E3E5DC`，主文字 `#17191C`，次文字 `#6B7268`。

### 5.3 字号与间距收敛

| 用途 | 规范 |
|---|---|
| 页面标题 | 28 / 700 |
| 区块标题 | 18 / 650 |
| 正文 | 14 / 400 |
| 辅助文字 | 12 / 400 |
| 侧栏一级 | 14 / 600 |
| 卡片圆角 | 14 |
| 控件圆角 | 10 |
| 卡片内边距 | 20 |
| 区块间距 | 24 |

不再出现 13.5 / 14.5 / 12.5 这类“半像素字号”。

### 5.4 动效克制

- 侧栏首次引导卡 **删除**。它解释的是内部改版，不是用户价值。
- 登录后页面 **不做滚动入场动画**；内容应立即可见。
- hover / 展开 150～200ms；尊重 `prefers-reduced-motion`。
- 侧栏只保留“收起/展开”一个动作，删除「版式」三选一弹层。

### 5.5 状态与可达性

- 导航按钮加 `aria-current="page"`；当前项只有一种高亮方式：左侧 3px 绿条 + 8% 浅底。
- 所有图标按钮有 `aria-label`；键盘焦点有 2px 可见轮廓。
- 客服改为**点击展开**，不再 hover 展开（触屏和键盘都更可靠）。
- 移动端所有可点区域 ≥ 44px。

## 6. 移动端：底栏代替抽屉

```
┌──────────────────────────────┐
│ 商城 · 成品号            🔔   │ 52px
├──────────────────────────────┤
│ [套餐代充] [成品号]           │
│ ┌──────────────────────────┐ │
│ │ 商品卡                   │ │
│ └──────────────────────────┘ │
│                              │
├──────────────────────────────┤
│ ⌂首页  ▤商城  ▣卡片  ◈钱包  (H)我的 │
└──────────────────────────────┘
```

- 5 个底栏项：首页 / 商城 / 卡片 / 钱包 / 我的。
- 顶栏只留页面标题 + 铃铛；余额在钱包页，不在小屏抢位置。
- 商品、充值、开卡等关键流程使用**底部粘性主按钮**。
- 安全区适配 `env(safe-area-inset-bottom)`。
- 原抽屉保留为“更多”兜底可以不做；如果要做，只放客服、帮助、演示工具。

## 8. 落地顺序与影响范围

### P0 · 导航骨架（0.5～1 天）

- 侧栏改成 5 个一级项 + 底部用户卡；删除二级树、`更多` 分组、`版式` 弹层。
- 顶栏删掉「编辑文案」「卡内余额」；余额合并为一个，客服保留图标。
- 页内页签接管原二级页面。
- 涉及：`app/page.tsx`（`sidebarGroups`、`handleSidebarNavigate`、`sidebarActiveId`）、`components/app-sidebar.tsx`、`app/globals.css`。
- 命名迁移追加到 `app/page.tsx` 的 localStorage 迁移链，**只追加，不改旧条件**。

### P1 · 页面收敛（1～2 天）

- 首页改个人总览；运营数据降级。
- 钱包去掉 6 宫格、合并页签。
- 订单默认「订单」。
- 充值页改专注模式。
- 涉及：`account-dashboard.tsx`、`wallet-page.tsx`、`orders-page.tsx`、`wallet-recharge-page.tsx`。

### P2 · 视觉统一（0.5～1 天）

- 统一 `PageHeader`；字号、间距、圆角、颜色收敛。
- 删除登录后滚动入场动画；导航 active 状态统一。
- 涉及：`app/globals.css`（建议新增 `.shell-v2` 作用域，稳定后再清理旧规则）。

### P3 · 移动端（0.5～1 天）

- 底栏 5 项、粘性主按钮、安全区。
- 断点回归：1440 / 1296 / 1024 / 768 / 390。

### P4 · 回归（0.5 天）

- `tsc --noEmit` 0 错误。
- 重点回归：余额不足续单、充值两段式查询、批量代充离开确认、站内信强制弹窗队列、卡片冻结/删卡。
- 更新 `CHANGELOG.md`，版本号建议 `0.23.0`，提交信息 `refactor: 菜单与界面大改（5 项一级导航 + 页内页签）`。

## 9. 不能碰的雷区

1. `components/payment-experience.tsx` 是四处复用组件，只加可选 props，不改默认行为。
2. `navigateTo` 统一跳转；`keepPendingOrder` 只有 `goTopupForOrder` 传 `true`。
3. 沉浸式子视图必须挂在 `selectedMenu === "xxx" && localState` 的主三元链上。
4. 站内信强制弹窗队列：确认后索引不变，不能改成 +1。
5. localStorage 文案迁移是链式的，新增改名要追加条件。
6. `app/globals.css` 已 376KB 且有多层覆盖；不要直接删旧规则，先加作用域层，回归后再清。
7. 构建前先停 dev server，否则会挂起。

## 10. 需要产品拍板的 5 个问题

1. **首页到底给谁看？** 普通买家 / 分销运营 / 两者都有？如果两者都有，是否加「经营视图」切换？
2. **「推广」是不是一级业务？** 如果是，保留第 6 个一级入口；否则放「我的 → 推广奖励」，首页留一张小卡。
3. **演示工具能否默认隐藏？** 建议「编辑文案 / 导配置 / 恢复默认」只在「我的 → 演示工具」出现，客户演示时不可见。
4. **移动端是否接受底栏？** 底栏更适合单手操作；如果必须保留抽屉，也可以，但入口仍按 5 项收敛。
5. **个人资料和账户安全是否合并？** 建议合并为「账户设置」两个页签，减少一个入口。
