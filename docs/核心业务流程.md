## 链路 1：成品号购买（弹窗 + 余额直付 + 余额不足续单）

**状态机**：

```
[商品列表/首页入口]
   │ 点「立即购买」（未登录先执行一键 mock 登录，不弹浮层不中断）
   ▼
[确认购买弹窗] AccountPurchaseDialog(stage="confirm")
   │ 确认支付（100% 扣钱包余额）
   ├── 余额充足 ──▶ [成功页] stage="success" ──▶ 完成
   └── 余额不足 ──▶ 挂起订单 setPendingOrder
                      │ goTopupForOrder → navigateTo("topup", {keepPendingOrder:true})
                      ▼
                 [钱包充值页]（顶部显示"正在为订单补足余额"提示条）
                      │ 充值成功
                      ▼
                 [充值成功页] 「返回订单继续支付」primary 按钮
                      │ resumePendingOrder()
                      ▼
                 回到商品页并重开购买弹窗 ──▶ 余额充足 ──▶ [成功页]
```

**关键文件**：`components/account-purchase-dialog.tsx`（弹窗容器 + 两段 stage）、`app/page.tsx`（pendingOrder 状态、goTopupForOrder、resumePendingOrder）、`components/wallet-recharge-page.tsx`（onResumeOrder / pendingOrderHint / initialAmount 三个可选 prop）

**改了会炸的坑**：
- `navigateTo` 里 `if (!options?.keepPendingOrder) setPendingOrder(null)` —— **全项目只有 goTopupForOrder 传 true**，漏传 = 挂起订单丢失 = 续付像坏的；改动后 `grep keepPendingOrder` 复核
- `resumePendingOrder()` 顺序有讲究：先 `setPendingOrder(null)` 消费掉 → navigateTo → **之后**才能 set 弹窗相关状态，顺序反了弹窗不出现
- 充值页金额初值 `useState(initialAmount ?? 100)`，**不要加 effect 同步**，靠 `selectedMenu==="topup"` 条件渲染保证跳来时是新挂载
- 余额来源 `effectiveBalance = isLoggedIn ? walletBalance : 0`；`walletBalance` state 不许改（applyPaymentCompletion 依赖累加）

## 链路 2：钱包充值（三步 + 查询到账两段式）

**状态机**：

```
[Step1 选充值金额] ──下一步──▶ [Step2 选支付网络 TRC20/ERC20] ──生成支付单──▶ [Step3 扫码支付]
                                                                              │
  Step3 面板：支付状态(等待付款) + 倒计时 + 应付金额 + 充值单号(PAY…)              │
  + 尾数高亮提醒 + 到账金额 + 收款地址/二维码                                    │
                                                                              │ 点「查询到账状态」(第 1 次)
  ◀── 返回修改支付方式（与查询按钮同行）                                          ▼
  │                                                     [status: confirming 链上确认中]
  │ (充值记录区可"恢复待支付充值单"回到 Step2)                                        │ 再点第 2 次
  └──────────────────────────────────────────────────▶ [充值成功页：到账金额/新余额/单号 RCG…/到账时间]
```

**关键文件**：`components/wallet-recharge-page.tsx`（三步状态机 1|2|3、finishPayment、queryArrivalStatus）、`components/payment-experience.tsx`（CryptoPaymentPanel 共享面板）、`data/payment-mocks.ts`（createPaymentIntent / completeMockPayment / paymentNetworks）

**改了会炸的坑**：
- 查询按钮**故意不用 setTimeout 自动完成**——防双击触发两次 completeMockPayment 导致余额重复累加；两段式天然防重
- `CryptoPaymentPanel` 是共享组件（充值页/代充向导/批量工作台/支付抽屉四处复用），充值页定制一律走**可选 props**（showTimeline / orderNo / amountNotice / showDemoControls…），别改默认行为
- 构建前必须停 dev server，否则构建挂起

## 链路 3：套餐代充（单账号 / 批量双模式）

**状态机**：

```
[套餐升级页] 选商品（ChatGPT / Claude × Plus / Pro / Max）
   │
   ├── 单账号模式 single ──▶ [填写账号信息表单] ──▶ 提交 Mock ──▶ [办理结果]
   │
   └── 批量模式 batch  ──▶ [粘贴多个 Session]
                            │ 解析（每条 parseStatus: parsing / success / failed）
                            ▼
                       [批量结果列表] 仅 Free 账号 eligible 可办理
                            │ 提交
                            ▼
                       [批量办理进度与结果]
   （单/批量可随时互相切换，切走会清当前页未提交内容，有离开确认弹窗）
```

**关键文件**：`components/recharge-wizard.tsx`（向导主体 + 单/批量模式 + Session 解析）、`components/recharge-batch-flow.tsx`、`data/recharge-flows.ts`

**改了会炸的坑**：
- 向导内有多个离开确认弹窗（exitOpen / delayOpen / leaveOpen），改流程时别把"未提交内容会被清空"的保护拆了
- 沉浸式子视图必须 `selectedMenu === "xxx" && localState` 挂在主渲染链上，**不许用局部状态短路三元链**（已踩过：wizardProduct && wizardFlow）
- 敏感信息保护是产品承诺：密码/Cookie/Session/Token/Authorization/MFA/验证码一律不提交、检测到即清空（`data/recharge-flows.ts` sensitiveDescription）

## 链路 4：站内信生命周期

**状态机（单条消息）**：

```
[后台视角] 创建(标题/内容/强制弹出/邮箱) ──上架──▶ [active 可见]
   │                                              │
   └── 下架 status="off" ──▶ [不可见]             ├─ 全局：所有人可见
                                                  ├─ 个人：仅邮箱匹配者可见
[过期 expiresAt < now] ──▶ [不可见]                │
                                                  ├─ 未读：计入角标；forced 消息自动弹窗(仅一次)
[可见且未读] ──点标题/弹窗确认──▶ [已读] ──▶ 不再弹窗、角标减少
```

**关键文件**：`components/site-messages.tsx`（铃铛 + 下拉面板 + 详情/历史弹窗 + 强制弹窗队列）、`data/messages.ts`（消息数据 + getVisibleMessages 过滤规则）

**改了会炸的坑**：
- 强制弹窗是**队列推进**：确认当前条后 `unreadForced` 会缩短一位，下一条顶到**同一索引**——推进逻辑写成"索引+1"会取到 undefined 直接崩（已踩过，修法：确认后索引不变，无下一条才置 -1）
- 空值判断必须防 `undefined` 与 `null` 双态（`?? null` 收敛后再比较）
- 可见性过滤规则（下架/过期不可见、不计未读）集中在 `getVisibleMessages`，UI 侧不要自行再过滤
- 铃铛面板是"点击展开、点击外部收起"（document pointerdown 监听），别改回 hover 模式
- 仅登录后渲染铃铛（`isLoggedIn` 门控在 app/page.tsx）

## 通用约定（四条链路共同遵守）

- **登录是假的**：一键 mock 登录，任何"未登录拦截"本质都是先登录再继续
- **导航统一走 `navigateTo()`**（会清 wizardProduct / paymentRequest 等现场），新增入口一律复用，不许自造跳转
- **渲染链纪律**：页面内容由 `selectedMenu === "xxx" ? ... :` 长三元链驱动，沉浸式子视图必须 `selectedMenu === "xxx" && localState` 挂链，禁止局部状态短路
- **文案默认值改动**：必须补 `app/page.tsx` localStorage 链式迁移（只匹配已知旧值），老用户才不会被卡死在旧文案
- **一切"将来要真的"的数据点**：以 `docs/接口契约梳理.md` 为准，Mock 结构不与契约打架
